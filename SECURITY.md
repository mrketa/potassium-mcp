# Security Policy

> **Windows Setup grants full access on a genuinely fresh installation.** The generic `agent` receives read, admin, and execute access, including synchronous `potassium_execute_luau` and asynchronous `potassium_execute_luau_async`, with no extra Setup warning, consent, or permission prompt. Arbitrary Luau can change the connected client and act with the permissions and capabilities of its executor. Connect only trusted agents: untrusted content or prompt injection may induce unwanted actions. Execution is not sandboxed.

Updates, repairs, and reinstalls with retained configuration preserve explicit existing permissions, including restrictions; they do not apply the fresh-install grant. A missing `agent` policy in existing configuration may receive a read-only entry, never elevation of admin, execute, or the global gate. There is no Safeproxy or bypass of harness/application approval. Authentication, token protections, loopback restrictions, truthful tool annotations, and resource limits remain active. Full fresh Windows access does not enable optional HTTP transports, built-in fallback, external HTTPS hosts, or wider trace/artifact roots.

The advanced npm CLI defaults are unchanged: read/admin/execute are independent policy axes, admin diagnostics need an explicit grant, and arbitrary Luau requires both the global unsafe gate and execute permission. Fresh Windows Setup sets those execution gates for its generic `agent`; it does not remove them. Read tools do not mutate game state; watches/references manage bounded bookkeeping. Do not include tokens, private artifact contents, submitted code, or local configuration in issues.

Per-host policy constrains trusted configured launchers, not malicious holders of the shared credential. A token holder can claim another known caller-supplied `hostId`; HMAC transcript binding protects against tampering, not token-holder impersonation. No adversarial per-host isolation or execution sandbox is provided. Keep token readers trusted, keep HTTP loopback-only, and do not add untrusted artifact roots or HTTPS allowlists.

Async submission can have indeterminate acceptance after a send/transport failure; never automatically replay it. An accepted job ID is acceptance evidence even if later audit/formatting fails, not completion. Queued cancellation prevents execution. Running raw-code cancellation is cooperative; a typed remote job whose dispatch started retains eventual return values/errors despite a cancellation request, keeping the execution lock until native return/error. FireServer local dispatch is not server acknowledgement. Recovery, disconnect, and local cancellation do not prove nonexecution or forcibly terminate arbitrary Luau, InvokeServer, untracked connections, or spawned work. Stateless HTTP cannot route cross-request cancellation to the previous request's server.

If the custom token may be exposed, use `potassium-mcp rotate-token` from the verified installed package, then reconnect affected hosts and reattach Potassium. Until publication is approved, use the verified candidate tarball rather than assuming a same-version npm artifact contains checkout changes. Repair preserves a proven valid token and is not rotation. Rotate the built-in fallback token through Potassium's native procedure; it must remain distinct. Never disclose tokens or weaken their ACLs.

Setup, repair, registration, and uninstall fail closed on unproven ownership, edited wrappers, foreign entries, or unsafe paths. The current custom OMP wrapper and junction must remain untouched until a separate proven migration. Do not delete evidence/credentials or overwrite user-managed files to make a check pass. `uninstall --all` retains private config, token, artifacts, and reinstall evidence; npm package removal is separate, and private-data purge requires a separate explicit destructive decision.

Filesystem containment uses bounded canonical-path/identity checks and best-effort snapshots, not atomic directory-handle containment or atomic pathname link/removal against last-instant ABA swaps. Do not treat an adversary-writable artifact/config parent as isolated solely by these checks. The covered exclusive-create parent-swap case can leave an empty temporary file outside the intended root; it writes no result bytes and deliberately avoids cleanup through an unsafe path rather than risking unrelated deletion. Redaction reduces known disclosure patterns; it is not exhaustive data-loss prevention or recognition of every secret format.

Retention windows are not exact real-time cleanup guarantees: terminal jobs, idle sessions, and artifacts prune lazily on relevant activity; terminal watches also have a one-second lifecycle sweep, subject to engine scheduling. References have explicit release and no TTL. Real engine behavior and every claimed platform/host require independent qualification; isolated fixtures do not prove sandboxing or live-game stability.

Remote inventory v2 changes bounded snapshot/reference bookkeeping under read permission. Explicit remote capture and temporal action observation require execute/global gates; discovery/capability reads install no hook. Selected capture retains outbound FireServer/InvokeServer namecall target/method/argument-type metadata, not values/tables/returns, and does not invoke/replay. Action observation adds bounded before/after state differences and temporal correlation, not automatic actions or proven causality. The separate `potassium_remote_call` helper queues one explicit typed invocation, validates references/types again before dispatch, and never compiles supplied strings. This is a real mutation surface, not a sandbox or blind bulk-discovery caller; permitted raw Luau remains unrestricted.

Actual game capture interception is unverified and `nativeSemanticsVerified` remains false. Native API availability, local newcclosure yield/error/identity probes, and disposable newproxy method/yield/readonly restoration do not qualify a game metatable or real RemoteFunction. Raw __namecall slot ownership checks detect replacement, not in-place hookfunction mutation with unchanged function identity. They are not an adversarial/universal foreign-hook guarantee. On lost slot ownership the observer becomes inert, does not overwrite the foreign slot, and blocks restart to avoid layers; an inert wrapper or readonly-restoration limitation can remain. Stop/expiry/teardown never claims to cancel already sent calls or arbitrary code. Do not reload the bootstrap through its own active MCP connection.

Compact result IDs are memory-only retrieval handles, not independent authorization. Each result_read rechecks scope and originating-tool permission after original validation and applicable redaction; expiry/eviction never reruns work. stdio/stateful HTTP scopes are separate and close releases their records; stateless HTTP shares one authenticated HTTP-policy scope across POSTs. The global count/byte budget permits eviction before the 120-second lifetime. Capture and inventory snapshot caches instead belong to the selected bootstrap generation and are shared among its trusted sessions; they do not provide adversarial multi-agent isolation. Lazy catalog activation only changes visibility of already permitted tools, never grants access. Metadata and redaction are not exhaustive DLP.

Offline `potassium_code_index`/`potassium_code_query` parse explicitly supplied Luau as data under read policy, with real Tree-sitter ASTs. They neither execute imports/source nor recover server source. File intake uses separate `sourceRoots`, restricted to explicit `.lua`/`.luau` files with traversal/absolute-path/ADS/link-redirection rejection and opened-file identity/version checks. Original roots are read by the trusted broker, not exposed to the parser. Root and parent ownership must remain trusted: these checks are best-effort filesystem containment, not atomic directory-handle isolation from an adversarial owner. Inline source needs no root. Fresh configuration alone initializes `workspace/potassium-mcp-sources`; existing configurations and artifact-reader source/secret blocking remain unchanged.

The production Windows x64 parser is a small GUI-independent native C worker (Tree-sitter `0.25.0`, Luau grammar `1.2.0`) in ordinary no-capability AppContainer, atomically assigned to a Job with single-process/256 MiB/5-second CPU/10-second wall limits. It receives bounded supplied-source input, not original source roots/config/token; handles/environment/output and its read-only staged executable are bounded. No private desktop/station is created and no existing UI ACL is edited. The C# controller handles bounded framing rather than parsing Luau; the trusted parent validates the returned native tree and runs bounded JavaScript semantic analysis. That host-side analysis is not itself described as OS-confined.

This is not LPAC, a Node worker-thread sandbox, or an absolute filesystem whitelist: Windows resources granted to ordinary AppContainers remain accessible. Actual local OS cases passed typed UTF-8 parsing, external-file/runtime-write denial, child quota (1816), a host-reachable loopback positive control with no inside connection (10060), CPU/memory/output/wall limits, cancellation, and crash recovery. These scoped results are not universal OS/host certification or a final full-suite pass. The fixed backend has no CHILD_PROCESS_POLICY or experimental debug paths. Unavailable/unsupported backends fail explicitly, without unconfined fallback. Native Zig `0.14.1` provisioning is build-time only, followed by self-contained ParserHost build; runtime downloads nothing. Web-tree-sitter/WASM remain development-test-only, never a production substitute. [Testing](docs/TESTING.md#parser-and-source-analysis-proof-boundaries) separates native proof from pending artifact/game acceptance.

Index retrieval is memory-only and scope/origin-permission bound, with four indexes, 8 MiB accounted source/8 MiB metadata aggregate, and ten-minute activity-pruned TTL. Display/snippets redact AST strings/comments/numerics and the configured token; source hashes remain separate, and incomplete redaction analysis denies source display. This does not detect every secret encoded in identifiers or establish exhaustive DLP. Dynamic/branch/loop/captured origins remain explicitly uncertain. `potassium_session_stats` retains only bounded counters/timing and salted scan-selection keys, never raw arguments/results/source/credentials or exported hashes. Stateless HTTP usage/index scopes are broker-shared for that authenticated policy, not adversarial caller isolation.

Report vulnerabilities privately to the maintainers with a minimal reproduction and impact description.
